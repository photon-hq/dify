# Privacy policy

Effective date: October 22, 2026

This Photon Bot endpoint for Dify processes the selected Photon environment (origin) and API key; the signing secret of the Photon webhook destination that delivers to the endpoint; the selected Dify app and the inputs set for it; the deliveries Photon sends to the endpoint: event and message identifiers, the project ID, space and user identifiers, platforms, message content, the handles and identifiers of senders and of the project's receiving lines and accounts, status, and timestamps; and the app's answers. These values can include personal data: message content, phone numbers, email addresses, and the platform identifiers of people who message the project on iMessage, SMS, WhatsApp, WhatsApp Business, email, or Telegram.

Dify stores the endpoint's settings, the API key and signing secret as secrets. For each space and app it answers in, the plugin keeps one record in its Dify plugin storage: the app ID and space ID, the ID of the Dify conversation it uses for that space, and the ID of the last message it started answering there. The record holds no message content. The plugin holds each delivery and answer in memory only while it handles them. It does not collect analytics, log credentials, log complete request headers, or log message content.

The text of each answered message goes to the selected app through Dify, with the inputs set for the app and the space's conversation ID; Dify processes and keeps it as a message of that conversation, with the app's answer. The app's own processing, such as its models, tools, and knowledge, is configured in Dify. To reply, the plugin transmits data only to the selected Photon origin over verified HTTPS: **https://api.photon.codes** for production (the default), or **https://api.staging.photon.codes** for staging. These are the only two accepted origins, and redirects are not followed. The API key is sent as a Bearer authorization credential, and the project ID of the delivery scopes the request. A reply transmits its space ID, the ID of the project's agent user that received the message, the answer text, and an idempotency key made from the received message's ID.

Photon processes and may retain the transmitted data, and the messages it delivers, under [Photon's privacy policy](https://photon.codes/privacy-policy). The plugin does not control Photon's retention. Photon receives messages from, and passes replies to, the network of each space's channel, which processes them under that operator's own terms: Apple for iMessage ([Apple privacy policy](https://www.apple.com/legal/privacy/)), mobile carriers for SMS, Meta for WhatsApp and WhatsApp Business ([WhatsApp privacy policy](https://www.whatsapp.com/legal/privacy-policy)), Telegram ([Telegram privacy policy](https://telegram.org/privacy)), and the email providers involved for email. Recipients receive and keep the replies sent to them. Apart from calling the selected app through Dify, the plugin itself contacts only the Photon API. Dify's deployment settings and policies determine retention of endpoint settings, plugin storage, conversations, app logs, and the data the app's model and tool providers receive.

There is no plugin-managed user-data collection, third-party analytics, advertising, or sale of data. Uninstalling the plugin does not erase data retained by Dify, Photon, channel operators, or message recipients; delete the Photon webhook destination to stop deliveries, and use those services' controls and policies.
