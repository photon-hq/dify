# Privacy policy

Effective date: October 21, 2026

This Photon Tool provider for Dify processes the selected Photon environment (origin), API key, project ID, sender ID, message type, message text, images passed to `send_message`, optional email subject, space identifiers, message, parent-message, and attachment identifiers, attachment metadata and content, idempotency keys, pagination tokens, platform filters, participant handles and user identifiers, other filters, message content, senders and recipients, status, timestamps, and acceptance and failure metadata needed for the requested action. These values can include personal data: message content, images, email subjects, phone numbers, email addresses, and the platform identifiers of people in a conversation on iMessage, SMS, WhatsApp, WhatsApp Business, email, or Telegram.

Dify stores the configured environment, API key, and project ID in its provider credential store. The plugin holds these values, and any image or attachment bytes, in memory during execution and persists nothing: no files, database records, message cache, or plugin storage. It does not collect analytics, log credentials, log complete request headers, or log message content. The plugin has no retention period of its own; transient data lasts only as long as the invocation.

For credential validation and the five tool actions, the plugin transmits data only to the selected Photon origin over verified HTTPS: **https://api.photon.codes** for production (the default), or **https://api.staging.photon.codes** for staging. These are the only two accepted origins, and redirects are not followed. Each request uses the selected environment only, with no automatic fallback to or simultaneous transmission to the other environment. The API key is sent as a Bearer authorization credential, and the project ID scopes the request. Sending a message transmits its space ID, sender ID, content, optional parent message ID, optional email subject, and idempotency key. To send images, the plugin first downloads each image from the file URL that Dify provides, then uploads the image bytes with their content type, size, and filename to Photon, and the message references the resulting attachment IDs. Listing spaces or messages, or getting a message or a user, transmits the required identifiers and the chosen filters or pagination tokens. Getting an attachment transmits its ID and returns its metadata to Dify, and its content to Dify as a file. Returned identifiers, space, message and user data, including the handles of senders, recipients and users, status, timestamps, and acceptance and failure details are provided to Dify. Errors carry Photon's HTTP status, error code, and stated reason; the plugin never returns the API key or HTTP headers.

Photon processes and may retain the transmitted data, including uploaded images, under [Photon's privacy policy](https://photon.codes/privacy-policy). The plugin does not control Photon's retention. To deliver a message, Photon passes it to the network of the space's channel, which processes it under that operator's own terms: Apple for iMessage ([Apple privacy policy](https://www.apple.com/legal/privacy/)), mobile carriers for SMS, Meta for WhatsApp and WhatsApp Business ([WhatsApp privacy policy](https://www.whatsapp.com/legal/privacy-policy)), Telegram ([Telegram privacy policy](https://telegram.org/privacy)), and the recipients' email providers for email. Recipients receive and keep the messages sent to them. Apart from downloading the images to send from the URLs Dify provides for them, the plugin itself contacts only the Photon API. Dify's deployment settings and policies determine retention of provider credentials, workflow inputs and outputs, files, execution histories, and logs.

There is no plugin-managed user-data collection, third-party analytics, advertising, or sale of data. Uninstalling the plugin does not erase data retained by Dify, Photon, channel operators, or message recipients; use those services' controls and policies.
